# Novel Propose — Web 小説提案オーケストレーター

ターゲットジャンル、コンセプト、プラットフォームを基に、3 つの差別化された Web 小説設計案を提案する。プラットフォームは指定された投稿プラットフォームのみを扱い、ユーザーが「どんな小説を書こうか」というところから始められるように発想段階を支援する。

## 実行モード: サブエージェント

## ワークフロー

### Phase 1: 入力パース

1. ユーザー入力から以下の項目を抽出する:
   - **ジャンル** (2026 年日本 Web 小説市場の主要ジャンル — 自由記述も可):
     - **男性向け**: 異世界転生／転移ファンタジー、ハイファンタジー、ローファンタジー、追放ざまぁ、VRMMO／VR ゲーム、現代ダンジョン／現代異能、異世界スローライフ／生産職／クラフト、領地経営／内政、ゲームファンタジー／ゲームスキル、おっさん／中年主人公もの、配信もの、戦記、ラブコメ
     - **女性向け**: 悪役令嬢／公爵令嬢／聖女もの、婚約破棄ざまぁ、異世界恋愛／ロマンスファンタジー、現代恋愛、TL (ティーンズラブ)、BL／ボーイズラブ、乙女ゲー転生
     - **共用**: 推理／ミステリー、ホラー、現代ドラマ、ヒューマンドラマ、お仕事小説／特殊職業もの、歴史・時代、SF (空想科学／宇宙／パニック)、エッセイ・ノンフィクション、ライトノベル (学園・青春)
     - **ジャンル組み合わせ可能** (例: 異世界転生×悪役令嬢、現代ダンジョン×ラブコメ、追放ざまぁ×スローライフ)
   - **コンセプト**: 職業、題材、雰囲気、差別化方向（自由形式）
   - **ターゲットプラットフォーム**: カクヨム、小説家になろう、アルファポリス、ノベルアップ+、エブリスタ、ノベルピア

2. **プラットフォーム正規化／検証ゲート**:
   - canonical name は `カクヨム`、`小説家になろう`、`アルファポリス`、`ノベルアップ+`、`エブリスタ`、`ノベルピア` のみ許可する
   - 以下の別名は canonical name に正規化できる:
     - カクヨム: `Kakuyomu`、`kakuyomu`、`カクヨム`
     - 小説家になろう: `なろう`、`Narou`、`narou`、`小説家になろう`
     - アルファポリス: `Alphapolis`、`alphapolis`、`アルファポリス`
     - ノベルアップ+: `NovelUp`、`novelup`、`ノベルアップ`、`ノベルアップ+`
     - エブリスタ: `Estar`、`estar`、`エブリスタ`
     - ノベルピア: `Novelpia`、`novelpia`、`ノベルピア`
   - 海外プラットフォーム名、許可集合外の国内プラットフォーム名、意味が曖昧な別名は自動マッピングしない
   - 許可されないプラットフォーム入力の場合は以下の文言で再質問する:

```
現在は以下の Web 小説プラットフォームのみ選択できます。
以下のいずれかを選択してください:
- カクヨム
- 小説家になろう
- アルファポリス
- ノベルアップ+
- エブリスタ
- ノベルピア
```

3. **欠落項目の質問**: ジャンルまたはプラットフォームが指定されていない場合、ユーザーに質問する:

```
Web 小説提案のためにいくつかの情報が必要です:

1. **ジャンル**: どのジャンルをご希望ですか？ (2026 年日本 Web 小説市場の主要ジャンル)
   - 男性向け: 異世界転生／転移、ハイファンタジー、追放ざまぁ、VRMMO、現代ダンジョン、異世界スローライフ／生産職、領地経営／内政、ゲームファンタジー、おっさん／中年主人公もの、配信もの、ラブコメなど
   - 女性向け: 悪役令嬢／公爵令嬢／聖女、婚約破棄ざまぁ、異世界恋愛／ロマンスファンタジー、TL、BL、乙女ゲー転生、現代恋愛など
   - 共用: 推理／ミステリー、ホラー、現代ドラマ、お仕事小説、SF、ライトノベル (学園)、エッセイなど
   - ジャンル組み合わせも可能です（例: 異世界転生×悪役令嬢、現代ダンジョン×ラブコメ、追放ざまぁ×スローライフ）

2. **プラットフォーム**: 主要な連載プラットフォームはどこですか？
   - カクヨム
   - 小説家になろう
   - アルファポリス
   - ノベルアップ+
   - エブリスタ
   - ノベルピア

3. **コンセプト／題材**（任意）: 特に扱いたい題材やコンセプトはありますか？
   （例: 医療、法曹、料理、建築、特定の時代背景など）
```

4. **作品仮題確定**: コンセプトが確定したら、ユーザーに作品仮題を確認する。

5. **カクヨムプリセットの提案** (プラットフォームがカクヨムの場合のみ):
   - プラットフォームが `カクヨム` に確定したら、「厳選大ヒット路線」プリセットの適用可否をユーザーに確認する
   - 正本: `${CLAUDE_PLUGIN_ROOT}/skills/design/references/platform-preset-kakuyomu.md`
   - 提案文言:

```
カクヨム向けに「厳選大ヒット路線」プリセットを適用できます。
- ターゲット: 偏差値 60 以上の高校・大学生／編集者層が好む感性（構造・伏線・考察を楽しむ層）
- スタイル: 短期カタルシス + 大量の長期伏線 + 二段の絶望(50%) + ラスト80%最強化 + 感情のジェットコースター + ハッピーエンド絶対遵守
- KPI: PV ランキングではなく書籍化スカウト／コンテスト評価

このプリセットを適用しますか？（はい／いいえ）
```

   - 適用する場合、後続の R1/R2/R5 リサーチと 3 案生成にプリセット方針（二層設計・大量の長期伏線・絶望と最強化の曲線）を反映する。3 案は「挑戦型」を主軸に構成する
   - 適用しない場合、従来どおりの汎用フローで進める

### Phase 2: 自動リサーチ（サブエージェント）

domain-researcher サブエージェントを呼び出して自動リサーチを実行する。ユーザーの待機なく即座に進める。

**サブエージェント: domain-researcher**
- subagent_type: `general-purpose`
- リサーチ項目:
  - **R1 ジャンル DNA**: 当該ジャンルの必須公式、読者期待、成功パターンの分析
  - **R2 プラットフォーム戦略**: ターゲットプラットフォームの収益モデル (課金モデル／無料公開＋書籍化／PV 還元モデル) と読者保持転換構造、読者傾向、人気作パターン
  - **R5 既存作分析**: 類似ジャンル／題材の既存 Web 小説を分析して差別化ポイントを抽出

- プロンプト:
```
あなたは domain-researcher サブエージェントである。
以下のリサーチを実行せよ:

1. R1 ジャンル DNA 分析:
   - ジャンル: {ジャンル}
   - 分析項目: 必須叙事公式、読者期待パターン、成功作の共通要素、差別化可能ポイント
   - `${CLAUDE_PLUGIN_ROOT}/skills/design/references/genre-dna-framework.md` を読みフレームワークを把握すること

2. R2 プラットフォーム戦略分析:
   - プラットフォーム: {プラットフォーム}
   - 分析項目: 収益モデル (課金モデル／無料公開＋書籍化／PV 還元モデル) と読者保持転換構造、読者傾向、人気ジャンル分布、無料／有料区間戦略 (無料公開モデルでは「無料公開区間」と「書籍化アピール区間」の概念に読み替えること)

3. R5 既存作分析:
   - ジャンル: {ジャンル}、題材: {コンセプト}
   - 分析項目: 類似題材既存作上位 10 作、各作品のセリングポイントと構造、読者反応（賛辞／不満）、共通クリシェ、差別化成功事例、未開拓領域
   - 3 案の差別化のため、既存作とのギャップ（gap）を明確に抽出すること

出力:
- _workspace/00_research/R1_ジャンル DNA.md
- _workspace/00_research/R2_プラットフォーム戦略.md
- _workspace/00_research/R5_既存作分析.md
```

### Phase 3: 提案生成（サブエージェント）

proposal-generator サブエージェントを呼び出して 3 つの差別化された設計案を生成する。

**サブエージェント: proposal-generator**
- subagent_type: `general-purpose`
- プロンプト:
```
あなたは proposal-generator サブエージェントである。
`${CLAUDE_PLUGIN_ROOT}/agents/proposal-generator.md` を読み、役割と出力構造を把握せよ。

以下の文書を読め:
- _workspace/00_research/R1_ジャンル DNA.md
- _workspace/00_research/R2_プラットフォーム戦略.md
- _workspace/00_research/R5_既存作分析.md

ユーザー入力:
- ジャンル: {ジャンル}
- コンセプト: {コンセプト}
- プラットフォーム: {プラットフォーム}

`${CLAUDE_PLUGIN_ROOT}/agents/proposal-generator.md` に定義された出力構造と作業原則に従い、3 つの差別化された Web 小説設計案を作成せよ。
R5 既存作分析結果を必ず参照し、既存作との差別化を明示せよ。

出力: _workspace/01_proposals.md
```

### Phase 4: ユーザー提示および選択

1. `_workspace/01_proposals.md` を読み、3 案を比較表で提示する:

```
## Web 小説設計案比較

| 項目 | 1 案: 正統派 | 2 案: 変奏型 | 3 案: 挑戦型 |
|------|------------|------------|------------|
| ログライン | ... | ... | ... |
| 差別化ポイント | ... | ... | ... |
| プラットフォーム適合度 | ★★★★★ | ★★★★☆ | ★★★☆☆ |
| 拡張性 | ... | ... | ... |
| リスク | ... | ... | ... |

どの案を選択しますか？（1/2/3）
あるいは特定案の要素を組み合わせたい場合はお知らせください。
```

2. ユーザーの選択を受ける。

3. 選択された案（または組み合わせ）をプロジェクトルートに `{作品仮題}_提案書.md` として保存する。

### Phase 5: 次ステップの案内

```
## 提案書を保存しました。

ファイル: {作品仮題}_提案書.md

### 次のステップ: 大きな設計（design-big）

提案書を基に小説全体の骨格を設計します:
- ブートストラップ文書（世界観、叙事起点、プラットフォーム戦略）
- キャラクターシート（主人公、協力者、ヴィラン階層）
- プロットフックガイド（叙事アーク、カタルシスリズム、読者保持転換 — プラットフォーム依存）

大きな設計を始めますか？
```

## エラーハンドリング

| 状況 | 戦略 |
|------|------|
| domain-researcher 失敗 | 1 回再試行。再失敗時は genre-dna-framework.md を基に提案を進め、レポートに「自動リサーチ未反映」を明示する |
| proposal-generator 失敗 | 1 回再試行。再失敗時はリーダーが直接 3 案を生成する |
| ユーザーが 3 案すべてを拒否 | 拒否理由を把握しコンセプトを再調整した上で Phase 3 を再実行 |
| ジャンルが genre-dna-framework.md にない | 類似ジャンルフレームワークを参照しつつ、当該ジャンル固有の読者期待を Web 検索で補強 |
| 許可されないプラットフォーム入力 | 自動変換せず、許可プラットフォームから再選択を要請 |
| 作品仮題未確定 | Phase 2 進行前に必ず確定。ファイル名に必要 |

## データフロー

```
[ユーザー] → ジャンル + コンセプト + プラットフォーム（投稿プラットフォームのみ許可、または質問後に確保）
    ↓
Phase 1: 入力パース + プラットフォーム正規化／検証 + 作品仮題確定
    ↓
Phase 2: domain-researcher サブエージェント → _workspace/00_research/（R1 + R2 + R5）
    ↓
Phase 3: proposal-generator サブエージェント → _workspace/01_proposals.md（R5 既存作分析を反映）
    ↓
Phase 4: 比較表提示 → ユーザー選択 → {作品仮題}_提案書.md
    ↓
Phase 5: 大きな設計（design-big）案内
```

## テストシナリオ

### 正常フロー
1. ユーザーが「現代ダンジョン×お仕事小説の Web 小説を提案して、カクヨムで連載するつもりで医療系がいい」と要請
2. Phase 1 でジャンル（現代ダンジョン×お仕事小説）、プラットフォーム（カクヨム）、コンセプト（医療）を抽出、作品仮題確認
3. Phase 2 で R1（ジャンル DNA） + R2（プラットフォーム戦略） + R5（既存作分析）の自動リサーチ
4. Phase 3 で 3 案生成（正統派: ダンジョン医療チーム結成もの、変奏型: 法医学＋ダンジョンミステリー、挑戦型: 医療 AI が異世界転生する SF）
5. Phase 4 で比較表提示、ユーザーが 2 案を選択
6. `{作品仮題}_提案書.md` 保存 + 大きな設計案内

### 入力不完全フロー
1. ユーザーが「小説を 1 つ作って」と要請
2. Phase 1 でジャンル／プラットフォーム／コンセプトすべての欠落を検出
3. 質問で情報収集 → ユーザーが「悪役令嬢、カクヨム、婚約破棄ざまぁ」と回答
4. 以降は正常フローと同一

### 許可されないプラットフォーム入力フロー
1. ユーザーが「異世界転生ものを提案して。プラットフォームは海外プラットフォーム」と要請
2. Phase 1 でプラットフォーム検証失敗
3. 「現在は以下の Web 小説プラットフォームのみ選択できます」の文言とともに 2 つのプラットフォームを再提示
4. ユーザーが「カクヨム」で再選択すれば正常進行

### 別名正規化フロー
1. ユーザーが「現代ファンタジー提案して。プラットフォームは Kakuyomu」と要請
2. Phase 1 で `Kakuyomu` を `カクヨム` に正規化
3. 以降すべてのリサーチ／提案／設定ファイルでは `カクヨム` を canonical 値として使用

### 組み合わせ選択フロー
1. Phase 4 でユーザーが「1 案の主人公に 3 案の世界観を合わせたい」と要請
2. 2 案の要素を組み合わせて新しい提案書を生成
3. 組み合わせた提案書をユーザーに確認後保存
