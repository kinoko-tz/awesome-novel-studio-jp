# Novel Design Router — 統合設計ルーター

ユーザーの設計要求を分析し、適切なスキルへ案内する。このルーター自体は設計を遂行しない。各段階の完了後に次の段階を案内するナビゲーターの役割を遂行する。

## ルーティングロジック

```
ユーザー入力分析:
├── 提案/発想キーワード: 「新しい小説」「小説の提案」「アイデア」「コンセプトを立てて」「どんな小説」
│   → propose へ案内
├── 曖昧な「新しい小説」要求: コンセプトがないかジャンル/プラットフォームが不明瞭
│   → propose へ案内
├── 統合キーワード: 「大設計と小設計」「全体 + 詳細」「統合設計」「両方」
│   → ユーザーへ事前案内した上で design-big を先に実行
│   → 大設計完了後に design-small を案内
├── 曖昧な場合: 「Web 小説の企画をお願い」「作品の設計」
│   → ユーザーへ範囲確認の質問
└── （大設計/小設計の明確な要求は big/small スキルが直接トリガー — ルーター経由は不要）
```

## 統合設計の案内文

```
統合設計は 2 段階で進行する:

1 段階: 大設計（design-big）
  - 作品全体のブートストラップ + キャラクターシート + プロットフックガイド
  - 自動リサーチ（domain-researcher）で専門分野資料を収集した後に設計を進行

2 段階: 小設計（design-small）
  - 25 話単位の詳細キャラクターシート + 詳細プロットフックガイド（推奨: 25 話ずつ順次進行）
  - 自動リサーチで該当アークの詳細資料を補強

大設計から開始する。
```

## 範囲確認の質問

```
どの範囲の設計が必要か。

0. **小説の提案** — まだコンセプトがなければ、ジャンル/プラットフォームに基づき 3 つの設計案を提案
1. **大設計** — 作品全体の骨格（ブートストラップ + キャラクター + プロット）
2. **小設計** — 25 話単位の詳細設計（例: 1～25 話 → 26～50 話 順次）（大設計文書が既に存在する必要がある）
3. **統合設計** — 大設計の後に小設計まで順次進行
```

## ナビゲーターの役割

各段階の完了時に次の段階を自動的に案内する:

| 現在の完了段階 | 次の案内 | 自動連結 |
|--------------|----------|----------|
| propose 完了 | 「提案書が保存された。大設計（design-big）を開始するか」 | ユーザー同意時に design-big を呼び出しつつ **提案書のパスを明示的に渡す**: 「プロジェクトルートの `{作品仮題}_提案書.md` を Phase 1 で必ずロードせよ」 |
| design-big 完了 | 「大設計が完了した。小設計（design-small）を開始するか」 | novel-config.md の存在確認後に案内 |
| design-small 完了 | 「小設計が完了した。次のアークの小設計を進行するか」 | — |
