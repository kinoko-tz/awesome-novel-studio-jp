# novel-config.md 作成ガイド

推敲スキルがプロジェクトごとに異なる設定を読み込むための **プロジェクト設定ファイル** の作成法。
各小説プロジェクトのルートに `novel-config.md` を作り、以下のセクションを埋める。

---

## 必須セクション

### 1. プロジェクト基本情報

```yaml
project:
  name: "小説タイトル"
  target_platform: "カクヨム"           # ターゲットプラットフォーム (カクヨム, 小説家になろう, アルファポリス, ノベルアップ+, エブリスタ, ノベルピアのみ対応)
  target_genre: "現代ファンタジー"           # ターゲットジャンル
  episode_dir: "episode/"           # エピソードファイルの場所 (ep001.md, ep002.md ...)
  work_dir: "revision/"             # fix_plan.md, learnings.md など推敲作業ファイルの場所
  design_dir: "design/"             # 設定文書ディレクトリ
```

> `project.target_platform` には canonical name のみを記録する。例: `カクヨム`, `ノベルピア`

### 2. 設定文書マッピング

推敲エージェントが参照する設定文書のパス。エージェントごとにどの文書を読むべきかを定義する。

#### 2-1. 共通文書 (全 EP)

| 文書キー | パス | 用途 |
|---------|------|------|
| character_core | design/character_sheet.md | キャラクターの核心定義、人物関係、固有設定 |
| character_detail | design/character_sheet_detail.md | ボイス表、呼称表、非言語タグ、関係変化、呼称転換条件 |
| dialogue_dna | design/character_sheet.md#dialogue-dna | Dialogue DNA (台詞固有性の定義)。キャラクターシート内のセクションまたは別ファイル。なければ character_detail で代替 |
| bootstrap | design/bootstrap.md | マクロ数値、世界観ルール、時系列 |
| writing_rules | CLAUDE.md | 執筆ルールのバイブル (rewrite 専用、既定値: プロジェクトルートの CLAUDE.md) |

#### 呼称転換条件 (選択)
関係の変化に応じて呼称が変わる場合、以下の形式で記述する。
| 話者 | 聞き手 | 転換トリガー (EP/イベント) | 転換前の許容 | 転換後の違反 | 等級 |
|------|------|----------------------|----------|----------|------|

#### 2-2. EP 範囲別の設定文書

以下の Markdown テーブル形式を **必ず** 遵守する。オーケストレーターがこのテーブルをパースして EP 番号に合うプロットガイドとキャラクターシートを自動選択する。

**パースルール:**
- `EP 範囲` 列: `EP{開始番号}~EP{終了番号}` 形式 (3 桁の数字、例: EP001~EP026)
- 範囲は **重複してはならない**
- 対象 EP がどの範囲にも属さない場合: 最後の範囲の文書を使用し `[範囲超過]` 警告を出力する
- 詳細プロットガイド/詳細キャラクターシート (小設計の成果物) が存在すれば優先使用し、なければ大設計文書を使用する

| EP 範囲 | ラベル | プロットガイドパス | 詳細プロットガイド (選択) | 詳細キャラクターシート (選択) |
|---------|--------|----------------|----------------------|----------------------|
| EP001~EP026 | 1幕 | design/plot-hook-guide_act1.md | | |
| EP027~EP076 | 2幕 | design/plot-hook-guide_act2.md | design/plot-hook-guide_act2_detail_ep027-076.md | design/character_sheet_detail_ep027-076.md |
| EP077~EP150 | 3幕 | design/plot-hook-guide_act3.md | | |

> オーケストレーターは対象 EP 番号が属する行のプロットガイドを `{PLOT_DOC}` として使用する。
> 詳細プロットガイド列にパスがあり、該当ファイルが存在すれば詳細ガイドを優先使用する。
> 詳細キャラクターシート列にパスがあり、該当ファイルが存在すれば共通の `character_detail` の代わりにこれを優先使用する。

#### 2-3. 補助参照 (選択)

| 文書キー | パス | 用途 |
|---------|------|------|
| web_novel_guide | design/web-novel-guide.md | モバイル最適化原則 (platform-optimizer 用) |
| verification | design/verification.md | 検証完了済み数値の記録 (story-analyst 用) |
| plot_macro | design/plot-hook-guide.md | 核心転換ポイントのマクロ (platform-optimizer 用) |

> **プラットフォーム別基準**: `_workspace/platform-guide-{platform}.md` ファイルがあれば platform-optimizer が当該プラットフォームの特化基準を自動適用する。プラットフォームは カクヨム, 小説家になろう, アルファポリス, ノベルアップ+, エブリスタ, ノベルピアのみ許可する。例: `_workspace/platform-guide-kakuyomu.md`, `_workspace/platform-guide-narou.md`

### 3. エージェント別の文書マッピング

各エージェントがどの軸を診断するときにどの文書を参照するかを明記する。

#### rule-checker
| 軸 | 参照文書キー | 用途 |
|----|------------|------|
| VOICE | character_detail | ボイス表 (終止語尾・長さ・パターン) との照合 |
| TITLE | character_detail | 呼称規則表 (話者×聞き手マトリクス)、呼称転換条件 |
| BANNED | character_core | 主人公の感情表現ルール (ある場合) |
| TRANS | — | grep ベース、設定文書は不要 |
| SILENCE | — | カウントベース、設定文書は不要 |

#### story-analyst
| 軸 | 参照文書キー | 用途 |
|----|------------|------|
| TIMELINE | plot_by_ep, bootstrap | EP 別の確定時間帯、出来事の順序 |
| NUMBER | plot_by_ep, bootstrap, character_core | EP 別の確定数値 (面積・資金・収穫量など) |
| PLAUSIBILITY | character_core | キャラクターの能力、時代考証 |
| SCENE | 直前 2 話 | 話間の連続性 (設定文書は不要) |
| UNIFORM | 直前 2 話 | パターン照合 (設定文書は不要) |

#### platform-optimizer
| 軸 | 参照文書キー | 用途 |
|----|------------|------|
| HOOK | plot_by_ep | EP 別のフック類型・感情強度、核心転換ポイント |
| OPENING | plot_by_ep | EP 別のビート構造 |
| MOBILE | web_novel_guide | モバイル最適化原則 |
| SUMMARY | — | 定量測定ベース、設定文書は不要 |

#### alive-enhancer
| 軸 | 参照文書キー | 用途 |
|----|------------|------|
| ALIVE-1 (こだま) | character_detail | 対話 DNA、キャラクター別の反応経路 |
| ALIVE-2 (沈黙) | character_detail | 非言語タグのパレット |
| ALIVE-3 (緊張点) | character_core | 脇役別の固有緊張点、核心的役割 |
| ALIVE-4 (距離感) | character_core | 主要な関係曲線、関係ルール |

#### revision-executor / revision-reviewer
| 校正/検証の類型 | 参照文書キー | 用途 |
|--------------|------------|------|
| TIMELINE/NUMBER | plot_by_ep, bootstrap | 正本数値の確認 |
| VOICE/TITLE | character_detail | ボイス表・呼称表の遵守校正 |
| キャラクター固有設定 | character_core | 主人公の能力、背景の正本 |
| ALIVE | character_detail | 非言語タグ・関係変化表 |

### 4. 保存ガードレール

校正時に絶対に損なってはならない要素のリスト。プロジェクトごとに異なる。

```markdown
1. 専門性の密度 (技術用語・データ)
2. 作品固有の雰囲気
3. キャラクターの専門家イメージ
4. 主人公固有の内面トーン
5. 時代考証
6. [キャラクター別の保存項目 — 例: 「キャラクターX の沈黙を保存」]
7. [関係ルール — 例: 「A-B 関係は一線を越えない」]
```

### 5. 数値クロス検証における正本の優先順位

数値の不一致を発見した際、どの文書を正本とするかの順序。

```markdown
1. plot_by_ep — EP 別の確定数値 (最も具体的)
2. bootstrap — マクロ数値、世界観ルール
3. verification — 検証完了済み数値の記録
4. 直前エピソード — 叙事の連続性
```

### 6. 核心転換ポイント

プロジェクトごとに、読者離脱の防止または有料転換のための核心エピソードを定義する。
該当エピソードはフック強度 4+ を必須とする。

```markdown
# 例 (プロジェクトに合わせて修正)
- EP025: 1幕終結 — 有料転換の誘導
- EP050: 中盤の転換点
- EP075: 3幕への進入
- EP100: クライマックスの前哨
```

> プラットフォーム別の既定転換ポイントがある場合は `_workspace/platform-guide-{platform}.md` に定義し、プロジェクトごとにオーバーライドする。

## 選択セクション

### 7. カタルシス類型

作品の核心となるカタルシス類型を定義する。自由テキストで記述。

```markdown
# 例
- 主人公の専門知識で危機を突破する知的快感
- 数字 (収穫量・売上) が証明する成長の快感
- 見下していた人物たちが認める逆転の快感
```

### 8. カスタム診断軸

12 軸以外にプロジェクト固有の診断が必要なら、このセクションに定義する。
story-analyst が LOGIC 診断時に併せて実行する。

カスタム軸は以下の 3 つを定義しなければならない:
1. **正本**: この軸の基準となる設定文書またはセクション
2. **検出キーワード**: grep で機械的に検出するパターンのリスト
3. **判別基準**: VIOLATION (違反) と ALLOWED (許容) の境界条件

#### 例 A: PASTLIFE — 転生/回帰設定の整合性 (回帰もの)

```yaml
custom_axis:
  name: PASTLIFE
  description: "主人公の転生/回帰設定とエピソード叙述の整合性を検証する"
  agent: story-analyst
```

レイヤー構成:
- **レイヤー 1 (キーワード直接違反)**: `grep "転生"` → 正本と矛盾する叙述を検出
- **レイヤー 2 (能力の暗黙的不整合)**: 転生能力マトリクスの検出キーワードを grep → 語り手の能力不整合を検出
- **判別**: 語り手が事実として記述した能力不足 = VIOLATION / 戦略的隠蔽・他者視点 = ALLOWED

続けて novel-config.md に正本要約、転生能力マトリクス (英語・システム・地域・専門分野別の水準＋検出キーワード)、等級基準を詳細に記述する。

#### 例 B: MAGIC_SYSTEM — 魔法体系の整合性 (ファンタジー)

```yaml
custom_axis:
  name: MAGIC_SYSTEM
  description: "魔法/能力体系のルールとエピソード叙述の整合性を検証する"
  agent: story-analyst
```

レイヤー構成:
- **レイヤー 1 (能力限界の違反)**: ブートストラップの魔法ルール (コスト・条件・限界) とエピソード内の魔法使用が矛盾するか検出
- **レイヤー 2 (成長曲線の違反)**: キャラクターの現在の等級/レベルでは不可能な魔法使用を検出
- **判別**: ルールの明示的違反 = VIOLATION / ルールの創造的応用・例外条件の充足 = ALLOWED

#### 例 C: RELATIONSHIP_LOGIC — 関係線の整合性 (ロマンス)

```yaml
custom_axis:
  name: RELATIONSHIP_LOGIC
  description: "キャラクター間の関係段階とエピソード内の行動/対話の整合性を検証する"
  agent: story-analyst
```

レイヤー構成:
- **レイヤー 1 (関係段階のジャンプ)**: キャラクターシートの関係段階表と現在 EP の行動が矛盾するか検出 (例: 警戒段階なのに突然スキンシップ)
- **レイヤー 2 (感情の逆行)**: 前話で確認された感情変化が説明なく前段階に回帰するか検出
- **判別**: 段階を 2 マス以上ジャンプ = CRITICAL / 1 マスのジャンプ (触媒イベントあり) = ALLOWED

### 9. 沈黙パターンの例外

沈黙の上限 (既定 4 回) から除外されるキャラクター。設定上、沈黙がアイデンティティであるキャラクター用。

```markdown
- キャラクターY (沈黙がキャラクターのアイデンティティ、置き換え禁止)
```

### 10. 核心数値のクイックリファレンス

エージェントが素早く確認できるよう主要数値を要約する。詳細値は設定文書の正本に従う。

```markdown
### 面積の進行
- 1幕: EP5(5万坪)、EP10(9.2t/ha)、EP26(60万坪)
- 2幕: EP36(480万坪)、EP71(3,000万坪=1万ha)

### 資金
- EP21 総資産: 10.9億円
- EP27 投資: $2.6M
```

### 11. カクヨムプリセット（厳選大ヒット路線）

`target_platform: カクヨム` で「厳選大ヒット路線」を採る場合のプリセット既定値。
詳細方針は `${CLAUDE_PLUGIN_ROOT}/skills/design/references/platform-preset-kakuyomu.md` を正本とする。
このプリセットを適用する場合、novel-config.md に以下を反映する。

#### ターゲット読者（上書き）
- 偏差値 60 以上の高校生・大学生／編集者・将来編集者になりそうな層が好む感性
- 構造・伏線・考察を楽しむ層。再読価値とハッピーエンドを重視

#### KPI（上書き）
- PV ランキングではなく **書籍化スカウト / コンテスト評価** を成功指標とする
- 課金転換は無い。コンテスト締切・試し読み終端 (1〜30 話) に筆力を集中する

#### カスタム診断軸（custom_axes に追記）

```yaml
custom_axes:
  FORESHADOW: "長期伏線を多層に配置し、物語 80〜100% 区間で回収する。設置→回収の対応表を design 段階で必須化する"
  DESPAIR: "各章 50% と物語 50% に『全てを失う絶望』を配置。50〜80% は再起の階段として短期カタルシスを刻む"
  EMOTION_SWING: "登場人物の感情を激しく上下させる。一話内でも振幅を作る"
  HAPPYEND: "各章末は『部分的勝利・希望の灯』を最低保証。物語全体は必ずハッピーエンドで着地する"
  DUAL_LAYER: "表層は一般読者向けの短期カタルシス、深層は考察層向けの長期伏線という二層構造"
```

#### ガードレール（追記）
- 物語をまたぐ大絶望は持続させてよいが、各章末の『希望の灯』は省略不可
- ラスト 80% で主人公が最強に近い存在となる成長曲線を厳守する

## novel-config.md の配置位置

```
{小説プロジェクトルート}/
├── novel-config.md          ← このファイル
├── design/
│   ├── bootstrap.md
│   ├── character_sheet.md
│   ├── character_sheet_detail.md
│   └── plot-hook-guide_act{N}.md
├── episode/
│   ├── ep001.md
│   ├── ep002.md
│   └── ...
└── revision/               (または work_dir に指定したパス)
    ├── fix_plan.md
    ├── learnings.md
    └── alive-tracker.md
```

## 推敲/rewrite スキルが設定を使用する方法

1. **Step 0 初期化**: `novel-config.md` を読み込み設定をパース
2. **EP 別の文書決定**: 設定の「EP 範囲別プロットガイド」から該当 EP のプロット文書を選択
3. **Phase 1 エージェント呼び出し**: エージェント別の文書マッピングに従い設定文書のパスをプロンプトに含める
4. **Phase 2-3 校正/検証**: 保存ガードレール、数値正本の優先順位を適用
5. **カスタム軸**: 定義されていれば該当エージェントに追加診断を指示

## Rewrite 専用設定 (選択)

rewrite スキルを使用する場合にのみ記述する。polish のみ使用するならこのセクションは不要。

### 対話 DNA ファイル

キャラクター別の対話 DNA (思考パターン、情報処理、説得方式、状況別の変奏) を定義したファイルのパス。
このファイルがなければキャラクター詳細文書 (character_detail) の `## 対話 DNA` セクションのみで診断する。

| 文書キー | パス | 用途 |
|---------|------|------|
| character_dialogue_dna | design/character-dialogue-dna.md | 対話 DNA — character-sculptor, episode-rewriter, episode-creator, quality-verifier が参照 |

**対話 DNA の定義位置** (優先順位順):
1. `character_dialogue_dna` のパスに別ファイルが存在すればこれを使用
2. 別ファイルがなければ、`character_detail` 文書内の `## 対話 DNA` セクションを使用
3. どちらもなければ: `[対話DNA未定義]` タグを付け、キャラクターのボイス表のみで診断 (精度が低いと警告)

**対話 DNA セクションの必須構造** (別ファイルでも character_detail 内のセクションでも同一形式):

```markdown
## 対話 DNA

### {キャラクター名}

#### 思考パターン
- **情報処理の方式**: [分析型/直観型/感情型/実用型]
- **意思決定スタイル**: [データ基盤/経験基盤/関係基盤/原則基盤]
- **説得方式**: [論理提示/感情訴求/権威引用/実例列挙]

#### 状況別の思考経路
| 状況の類型 | 思考経路 | 台詞例 |
|----------|----------|----------|
| 良い知らせ | [反応パターン] | 「やった、これで前に進める」 |
| 危機 | [反応パターン] | 「落ち着け。まず損失を数えろ」 |
| 葛藤 | [反応パターン] | 「あなたの言い分は分かる。でも譲れない」 |
| 情報伝達 | [反応パターン] | 「結論から言う。原因は三つだ」 |

#### 禁止パターン
- このキャラクターが絶対に言わない言葉/思考方式のリスト
```

### Rewrite 保存ガードレール

polish の保存ガードレールに追加される rewrite 専用のガードレール。

```markdown
1. 驚愕の表現は置き換え不可 — 各キャラクター固有の驚愕の言葉を他のキャラクターに移植しない
2. [主人公の動機表現ルール — 例: 「目標の数字を直接宣言しない」]
```

### Rewrite 作業ディレクトリ

```yaml
rewrite_work_dir: "revision/"  # rewrite-plan.md, rewrite-log.md の場所 (polish の work_dir と同じなら省略可)
```
